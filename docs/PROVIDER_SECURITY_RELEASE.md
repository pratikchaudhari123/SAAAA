# Provider and security pilot
- TallyPrime: configured server-side per deployment tenant and company, XML HTTP export collection, read-only latest ledger snapshot, digest and safe error. Private LAN or authenticated VPN only; never expose unauthenticated port 9000 to internet. Exact Tally version, license, XML encoding and company-specific response must be tested. No voucher import or ledger reconciliation.
- Razorpay: fixed HTTPS API, test keys only, tenant-scoped server-created INR orders, HMAC callback verification and server-side capture/amount/currency/order verification, manual refresh and local seven-day expiry marker. No real charge, FeeReceipt or ledger posting. No live keys, webhook, automatic scheduled reconciliation, refunds or settlement handling. Provider-side payment may still succeed after local expiry; recheck before retry. Test orders are not real dues.
- Credentials are server environment only. SAAAA_TALLY_TENANT, SAAAA_TALLY_URL, SAAAA_TALLY_COMPANY; SAAAA_RAZORPAY_TENANT, SAAAA_RAZORPAY_KEY_ID, SAAAA_RAZORPAY_KEY_SECRET. One configured tenant per provider per deployment. Do not paste secrets into chat or commit env files.
- SAAAA_CRITICAL_CIDRS comma-separated exact CIDRs, optional, fail closed for invalid configured networks. Checks immediate TCP peer; ignore forwarded headers. A trusted reverse proxy must separately enforce client-address restrictions; enabling in Docker without considering proxy topology may block access or admit proxy traffic. No institution-specific policy UI, login restriction, rate limit, or penetration test. Redacted tenant request audit for writes and existing application events; not complete before/after or tamper-proof auditing. No payloads stored.
- SLA overdue alerts persisted once per deadline type; admin scan and management command python manage.py scan_support_sla. Host scheduler must be configured separately; no email/SMS/WhatsApp delivery. Existing alerts visible in support ticket details.
- Migration 0017 adds four models (expected 73 campus tables). Four test methods use mock provider responses, no actual provider network. 46 expected backend test methods. Existing live checks retained. No full NEP, historical migration, production integration or security compliance claim.
